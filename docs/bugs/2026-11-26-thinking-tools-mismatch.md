# 思考记录和工具清单对不上，接口报 400

- 发现：2026-11-26，真飞书里
- 带来这个 bug 的改动：2026-11-24 的"访客说话时不给服务器那边的搜索工具"
- 状态：已修；修完后还没在真飞书里重试

## 1. 现象

飞书群里有一位访客。访客先说了一句话，Agent 正常回了。接着用户本人说"查一下某某的价格"，Agent 回：

> 模型接口出错了，这条我没处理完。过一会儿再发一次。

再发一次还是一样。只要这个会话不重新开始，用户本人说什么都是这句。

## 2. 怎么查的

**第一步：看日志。** 用量记录（`trace.jsonl`）里，出错那一轮群里别的 Agent 都有记录，唯独主 bot 没有。
用量是调模型成功以后才记的，所以能确定：是主 bot 这一次调模型失败了。但失败的原因没有记下来，
终端里也只打印了错误的名字。这是第一个教训：**失败的那一次，恰恰是最需要记下原因的那一次。**

**第二步：猜是限流，猜错了。** 出错的那一分钟，正好有另一个程序在用同一把密钥跑评测。
于是发了一个最小的请求，读接口回来的额度：每分钟 200 万 token，远远没到。排除。

**第三步：照着当时的情况重走一遍。** 在工作区的副本上，先让"访客"说一句，再让"用户"说一句。
第二句先用接口的"只数 token"功能检查（这个功能免费，但会检查请求合不合法）。错马上出来了：

```
BadRequestError 400
messages.1.content.0: Invalid `signature` in `thinking` block.
The block is bound to a different conversation. ...
The `tools` list differs from the one this block was created ...
```

到这里原因就清楚了。

## 3. 原因

一句话：**对话中途工具清单变了，历史里的思考记录就不能再发回去。**

展开说：

1. 模型回复时，除了说的话和要用的工具，还可能带一段**思考记录**（`thinking` 块，是它的草稿）。
   我们把模型的整个回复原样留在对话历史里，下次调用时一起发回去。
2. 接口有一条规定：思考记录带着一个签名，签名和"产生它时的那份工具清单、提示词"绑在一起。
   再发回去的时候，清单多一个工具、少一个工具、哪个工具的说明改了一个字，签名都对不上，接口拒绝整个请求。
3. 我们有一条安全规则：访客说话时，不给"让模型那边的服务器去搜索、读网页"这两个工具。
   这两个工具是服务器执行的，不经过我们自己的工具门禁，唯一能拦的办法就是不放进清单。
   所以访客那一轮发出去的工具清单，比平时少两个。
4. 于是：访客那一轮里产生的思考记录，绑的是"少了两个工具的清单"。轮到用户本人说话，清单变回完整的，
   历史里那段思考记录对不上，400。

为什么之前没发现：

- 只有"让服务器搜"的时候清单才会变。用自己写的搜索工具时，访客那一轮清单不变（靠工具门禁拦），不会出错。
- 评测题里没有"访客和用户轮流说话"的题，假模型的测试里也没有思考记录。
- 要"访客先说、用户后说"才触发，平时用户一个人聊不会碰到。

## 4. 怎么修的

修了两次。

**第一次：去掉对不上的思考记录。** 在 `agents/loop.py` 的 `run_agent()` 里，访客这一轮开始前去掉历史里的思考记录，
结束后把这一轮新产生的也去掉；一轮中间不动，因为接口要求用工具时把这一轮的思考记录原样带回去。
去掉的只是草稿，说过的话和用过的工具都在。

这样能用，但是个补丁：以后别的地方再改清单，还会撞上同一条规定。

**第二次：让清单不再变。** 同一天，用户决定访客的能力和本人一样（"人是我邀请的"）。
访客那一轮不再拿掉任何工具，清单从头到尾是同一份，这个 bug 的根就没有了。第一次加的那段代码随之删掉，
`run_agent()` 回到只有一个循环的样子，只在说明里留了一句提醒。

没有选的办法：

- 官方给的完整做法是：工具清单永远不动，要撤掉一个工具时往对话里追加一条"撤掉某工具"的消息。
  这是测试版功能，要带额外的请求头，对这个项目来说太重。
- 让接口自己丢掉对不上的思考记录（也是测试版功能）。同样没用。

顺带补上的：接口拒绝请求时，`call_model()` 把接口给的原因打在终端里，不再只打错误的名字。

## 5. 怎么确认修好了

- 第一次修完：把第 2 节第三步重跑，原来报 400 的请求，接口说合法。
- 第二次改完：假模型测试里加了一项，专门盯住"用户说、访客说、用户再说，四次调用发出去的工具清单和提示词一模一样，
  思考记录一段不丢"。以后谁又在中途改清单，这一项会报错。
- 还没做的：修完以后没有在真飞书里照原样重试。

## 6. 学到的

1. **一段对话从头到尾，工具清单和提示词不能变。** 要变（开关能力、换人设），就让这段对话重新开始，像 `/packs` 那样。
   这条规定和提示词缓存的"只认开头"是一个道理，两样都要求前面的内容一个字不动。
2. **调接口失败时，把对方给的原因记下来。** 只记错误的名字，等于没记。
3. **猜原因之前先想办法让它再出一次。** 限流是猜的，白查了一轮；照原样重走一遍，一次就拿到了接口的原话。
4. **接口有"只数 token"这种不花钱、又会检查请求的功能，查这类错很好用。**
5. **"两个人轮流说话"这种情况要有测试。** 每个功能单独测都是对的，合在一起才出错。
